Câu 1 (10 điểm): Phân biệt position: relative và position: absolute

1. Khái niệm

  • position: relative: Định vị phần tử tương đối so với vị trí ban đầu của nó. Phần tử vẫn giữ chỗ trong bố cục.
  • position: absolute: Định vị phần tử theo phần tử cha gần nhất có position khác static. Phần tử bị loại khỏi luồng bố cục thông thường.

2. Ví dụ minh họa

.container {
    position: relative;
    width: 300px;
    height: 200px;
}

.box {
    position: absolute;
    top: 10px;
    right: 10px;
}

Trong ví dụ trên, .container làm mốc định vị, còn .box nằm cách mép trên và mép phải 10px.

  • Relative: Thường dùng để dịch chuyển nhẹ phần tử hoặc tạo mốc định vị cho phần tử con.
  • Absolute: Thường dùng để đặt biểu tượng thông báo trên ảnh, nút đóng ở góc hộp thoại hoặc nhãn trên sản phẩm.

3. Responsive và hosting

Khi thiết kế responsive, nên kết hợp đơn vị %, rem, max-width và media queries để bố cục thích ứng với nhiều kích thước màn hình. Nếu sử dụng absolute quá nhiều, các phần tử có thể chồng lấn trên điện thoại.

Hai thuộc tính này không ảnh hưởng trực tiếp đến việc deploy lên hosting. Tuy nhiên, cần kiểm tra website trên nhiều trình duyệt và thiết bị để bảo đảm giao diện hiển thị chính xác sau khi triển khai.

Câu 2 (10 điểm): Quy trình đăng ký domain và cấu hình hosting

1. Quy trình thực hiện

  1. Đăng ký domain: Chọn tên miền, ví dụ mywebsite.com, tại nhà đăng ký tên miền.
  2. Chuẩn bị website: Hoàn thiện các file HTML, CSS và JavaScript.
  3. Chọn hosting: Tải mã nguồn lên hosting hoặc kết nối repository GitHub với nền tảng triển khai.
  4. Cấu hình DNS: Trỏ tên miền đến địa chỉ hoặc hệ thống máy chủ của hosting theo hướng dẫn của nhà cung cấp.
  5. Kiểm tra website: Truy cập tên miền, kiểm tra chức năng và bật HTTPS.

2. Vai trò của DNS

DNS (Domain Name System) giúp chuyển đổi tên miền thành địa chỉ IP hoặc thông tin đích cần thiết để trình duyệt tìm đến máy chủ website.

Ví dụ: Khi người dùng nhập mywebsite.com, DNS giúp trình duyệt tìm đến hệ thống hosting tương ứng.

3. Công cụ hỗ trợ deploy

  • GitHub Pages: Miễn phí, phù hợp với website tĩnh sử dụng HTML, CSS và JavaScript.
  • Netlify: Hỗ trợ deploy từ Git, cấu hình tên miền và HTTPS thuận tiện.
  • Vercel: Hỗ trợ triển khai website tĩnh và các ứng dụng web hiện đại.

4. Rủi ro bảo mật

  • Không bật HTTPS có thể khiến dữ liệu truyền đi thiếu an toàn.
  • Đưa API key hoặc mật khẩu vào JavaScript phía client có thể làm lộ thông tin.
  • Cấu hình DNS sai có thể khiến website không truy cập được hoặc dẫn người dùng đến địa chỉ không mong muốn.
  • Phân quyền hosting không đúng có thể làm lộ hoặc bị sửa đổi dữ liệu.

Vì vậy, cần bật HTTPS, bảo vệ thông tin bí mật, phân quyền hợp lý và kiểm tra cấu hình DNS.

Câu 3 (10 điểm): So sánh let, const và var trong JavaScript

1. Sự khác biệt

Đặc điểm var let const
Phạm vi Hàm hoặc toàn cục Khối lệnh {} Khối lệnh {}
Hoisting Được khởi tạo với undefined Được đưa lên nhưng chưa thể truy cập trước khai báo Tương tự let
Khai báo lại cùng phạm vi Có Không Không
Gán lại giá trị Có Có Không

2. Ví dụ lỗi thường gặp

if (true) {
    let age = 20;
}

console.log(age); // ReferenceError

Giải thích: Biến age chỉ tồn tại bên trong khối if, nên không thể truy cập ở bên ngoài.

Một lỗi khác khi dùng var:

console.log(name); // undefined
var name = "An";

Do var được hoisting và khởi tạo bằng undefined, câu lệnh không báo lỗi nhưng kết quả không phải giá trị mong đợi.

3. Cách debug bằng Chrome DevTools

  1. Nhấn F12 hoặc Ctrl + Shift + I để mở DevTools.
  2. Chọn tab Sources, đặt breakpoint tại dòng có lỗi.
  3. Tải lại trang và quan sát quá trình chạy.
  4. Kiểm tra giá trị biến trong mục Scope hoặc dùng Console để xem thông báo lỗi.

Kết luận: Nên ưu tiên const khi không cần gán lại biến, dùng let khi cần thay đổi giá trị và hạn chế sử dụng var để tránh lỗi phạm vi.

Câu 4 (10 điểm): Event Delegation trong JavaScript

1. Khái niệm

Event Delegation (ủy quyền sự kiện) là kỹ thuật gắn một trình xử lý sự kiện vào phần tử cha để xử lý sự kiện phát sinh từ các phần tử con thông qua cơ chế nổi bọt sự kiện (event bubbling).

2. Ví dụ danh sách động

<ul id="list">
    <li>Sản phẩm 1</li>
    <li>Sản phẩm 2</li>
</ul>

<button id="add">Thêm sản phẩm</button>
const list = document.getElementById("list");

list.addEventListener("click", function(event) {
    if (event.target.tagName === "LI") {
        alert(event.target.textContent);
    }
});

document.getElementById("add").addEventListener("click", function() {
    const item = document.createElement("li");
    item.textContent = "Sản phẩm mới";
    list.appendChild(item);
});

Giải thích: Khi nhấn vào một phần tử li, sự kiện nổi bọt lên ul và được xử lý tại đó. Các phần tử mới được thêm vào vẫn hoạt động mà không cần gắn sự kiện riêng.

3. Lợi ích khi kết hợp HTML/CSS

  • HTML: Tạo cấu trúc danh sách và các phần tử con.
  • CSS: Tạo giao diện, hiệu ứng hover và trạng thái tương tác.
  • JavaScript: Xử lý sự kiện tập trung tại phần tử cha.

Event Delegation giúp giảm số lượng trình xử lý sự kiện, tiết kiệm bộ nhớ và thuận tiện khi quản lý danh sách động. Nhờ đó, mã nguồn dễ bảo trì và có thể cải thiện hiệu suất khi danh sách có nhiều phần tử.
